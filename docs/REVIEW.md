# 代码审查记录

日期：2026-10-19。

本轮检查覆盖请求参数到 ORM 查询参数的构造、分类映射、搜索输出、播放线路过滤、XML 序列化和 PHP 版本兼容。原始兼容修复与本轮审查改进分为两个提交，便于回溯和部署。

## 已解决的问题

| 问题 | 影响 | 处理 |
| --- | --- | --- |
| 分类排序重建数字键 | 分类名称和扩展设置对应错误 | 使用保留键的排序，共用比较函数 |
| 不解析 `f` | 影视筛选失效 | 集中解析白名单条件，保留平铺参数优先级 |
| 精简列表不返回封面 | 触发影视的搜索结果过滤 | 查询补充 `vod_pic` 和 `vod_year` |
| 任意 `order_by` 直接组成排序表达式 | 请求可影响数据库排序表达式 | 排序列与界面选项共用固定白名单 |
| 平铺数组值可进入分类查询条件 | ORM 可能把数组解释成查询操作符 | 丢弃非标量筛选值 |
| 默认筛选覆盖显式条件 | 选择年份或清空地区后结果仍受默认值限制 | 仅对缺失参数应用默认值，计算缓存键前完成 |
| 对 HTTP 参数再次解码 | `+`、百分号文本被改变 | 依赖 HTTP 层解码，输入过滤只保留 trim |
| 年份解析依赖字符串长度 | 无效年份可能读取未初始化变量 | 独立解析单年与范围，无效值忽略 |
| 线路过滤重复、调用不存在的全局方法 | 配置播放器过滤时可能报错，名称与地址可能错位 | 统一按线路索引筛选相关字段，再转换显示名称 |
| `str_contains()` 用于 PHP 7.4 环境 | 指定播放来源时可能报错 | 改为精确匹配来源列表，避免依赖 PHP 8 函数 |
| 线路名称做子串匹配 | 相近名称可能选中错误线路 | 按完整标识符匹配 |
| 数组边界、已删除分类、未知播放器 | 警告或响应字段缺失 | 保留空槽位及原始播放器标识，容忍缺失分类 |
| XML 未统一转义、CDATA 可被提前结束 | 特殊字符使响应失效 | 共用文本及 CDATA 编码方法，验证完整 XML |

## 可读性与结构

- 将请求合并、默认条件、年份、排序和线路筛选拆成职责明确的方法，保留单文件安装方式。
- 排序字段和界面排序选项共用一份定义，减少修改时遗漏的可能。
- 详情与精简列表共用线路过滤；JSON 与 XML 共用图片地址处理。
- 详情响应按分类 ID 直接查找，不再执行只用于分类显示的排序。
- 删除失效的注释代码、未使用变量和多余引用，释放确实需要的循环引用。
- 沿用 MacCMS 控制器接口及原有公开方法，避免为这次修复引入运行时依赖。

## 验证范围

`tests/compat.php` 把警告转换为异常，使用缓存和模型桩调用控制器公共入口。检查涵盖初始三个兼容问题、参数优先级、恶意或无效排序/数组输入、默认值、年份范围、线路重排及 XML 特殊字符。GitHub Actions 使用固定提交的 Action，在 PHP 7.4、8.1、8.5 运行。

模型桩验证的是控制器交给 ORM 的参数和序列化行为，完整 MacCMS 数据库、采集插件和客户端的联合运行仍需部署环境验证。服务器此前部署的是第一笔兼容修复，本轮审查后的代码尚未同步到生产环境。

## 后续可选优化

1. **分类规模较大时预建父子索引。** 当前生成每个父分类的筛选项都会遍历分类表；分类数量通常较少，尚未测得性能瓶颈。确有大量分类时，可按 `type_pid` 分组后复用。
2. **明确详情响应字段契约。** 详情查询保留上游 `*`，避免漏掉不同 MacCMS 插件所需字段。建立客户端兼容样本后，可以考虑更明确的字段投影。
3. **采用统一格式化规则。** 本轮主要整理改动过的逻辑；后续持续开发可单独提交项目格式化，避免把大范围排版变化混入行为修复。
